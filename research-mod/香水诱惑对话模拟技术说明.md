# 香水诱惑对话模拟技术说明

## 1. 功能定位

“诱惑模拟（香水）”用于在战斗修改菜单中查看敌人的原版香水诱惑事件。

当前实现是“读取并模拟公共事件”，不是直接调用原版战斗诱惑流程。因此：

- 会播放原事件中的对话、选项、图片和音效；
- 会按选项进入对应分支；
- 不会自动执行原事件中的扣血、加状态、战斗结算、变量修改、开关修改等指令；
- 模拟结束后回到诱惑对话列表。

如果需要完全执行原版效果，应另行设计“直接启动公共事件/战斗事件”的方案，不能简单复用本模拟器。

## 2. 入口与数据来源

主要代码位于：

`Patch/zzzz_gouqi_Research_Mod.rb`

入口流程：

1. `open_research_mod_temptation_dialogue`
2. `research_mod_temptation_perfume_battler_entries`
3. `ResearchMod.enemy_perfume_dialogue_entries(enemy)`
4. 读取 `$data_common_events[2000 + enemy_id]`
5. `enemy_perfume_event_flow` 将公共事件转换为节点列表
6. `play_research_mod_temptation_nodes` 播放节点

敌人 ID 的取得会优先使用敌人的基础数据库 ID；无法取得时才从实例的 `enemy_id` 进行范围换算。香水事件编号规则是：

```text
公共事件 ID = 2000 + 敌人数据库 ID
```

例如敌人 010 使用公共事件 2010。

## 3. 事件解析结果

解析器 `parse_enemy_perfume_event_nodes` 将事件指令转换成以下节点：

```text
:message       对话窗口
:choice        原版选项及分支
:conditional   条件分支（111/411/412）
:terminate     结束事件处理（分支内部的 115）
:picture_show  显示图片（231）
:picture_move  移动图片（232）
:picture_erase 删除图片（235）
:sound_effect  播放音效（250）
```

`117` 公共事件调用会递归读取被调用的公共事件，例如 1999、2000 等。

## 4. 选项和分支规则

原版 `Window_ChoiceList` 返回的选择索引是从 0 开始的，因此必须使用：

```text
第一项 = 0
第二项 = 1
```

播放时会将选项压入 `$game_message.choices`，通过 `$game_message.choice_proc` 接收选择结果，再按 `choice_index` 找到对应分支。

### 空分支

部分原事件的选项分支本身没有台词，真正后续内容位于 `404` 之后。例如敌人 010 的“誘惑に乗る”分支就是空分支。

播放器必须在空分支结束后继续播放选择节点后面的节点，否则会出现：

- 选择“誘惑に乗る”后直接返回列表；
- 只播放第一句，不播放“うそ……？　引っ掛かった……！？”；
- 后续选项不出现。

### 结束指令 115

`115` 表示结束当前事件处理，但顶层香水事件开头可能有初始化条件块，其中也可能出现 `115`。因此当前实现只把条件分支内部的 `115` 转换为 `:terminate`，避免事件刚开始就被错误终止。

## 5. 条件分支

事件中的 `111`、`411`、`412` 会被转换为 `:conditional` 节点。播放时根据当前游戏状态选择真分支或假分支。

目前支持的主要条件包括：

- 开关；
- 变量比较；
- 队伍中是否有角色；
- 角色名称、职业、技能、武器、防具、状态；
- 敌人存活和状态；
- 金币；
- 物品、武器、防具持有；
- 脚本条件（`eval`）。

条件分支非常重要。不能将 `111` 下的所有消息直接展开，否则同一段事件中的索尼娅、爱丽丝、伊莉亚斯等互斥台词会被全部连续播放。

## 6. 图片和音效

### 图片

原版图片指令的参数格式如下：

```text
231: [图片编号, 文件名, 原点, 坐标模式, X, Y, X缩放, Y缩放, 不透明度, 混合模式]
232: [图片编号, 速度, 原点, 坐标模式, X, Y, X缩放, Y缩放, 不透明度, 混合模式, 持续时间, 等待]
235: [图片编号]
```

坐标模式为 0 时直接使用 X/Y；坐标模式为 1 时从 `$game_variables` 读取 X/Y。

战斗中使用 `$game_troop.screen`，因为 `Spriteset_Battle` 会从该屏幕读取图片。若错误地使用 `$game_map.screen`，图片可能不显示。

### 音效

事件指令 250 的参数是 `RPG::SE` 对象，应调用其 `play` 方法。

### 常见图片错误

如果出现：

```text
ArgumentError: bad value for blend_type
```

通常是图片参数错位，把不透明度 255 当成了混合模式。必须严格区分 `@params[8]`（不透明度）和 `@params[9]`（混合模式）。

## 7. 原生选项窗口定位

播放模拟选项时设置：

```text
@research_mod_choice_right = true
@research_mod_choice_bottom_y = 对话框顶部 Y 坐标
```

`Window_ChoiceList#update_placement` 会将选项窗口右对齐，并让底部贴合对话框顶部。播放结束后必须清理这两个临时实例变量，否则其他菜单的原生选项窗口可能继续使用香水模拟的位置。

## 8. 可能的错误与排查方法

### 8.1 选择后直接返回列表

重点检查：

- 事件是否被错误解析为只有开场消息和第一组选项；
- `117` 嵌套公共事件解析是否抛出异常；
- 空分支是否继续了 `404` 后的节点；
- 是否错误地把顶层 `115` 当成结束节点。

### 8.2 所有选项都继续播放

通常是忽略了 `115`，或者没有把分支结束状态向外层返回。应确认失败分支中的 `115` 会返回 `true`，并停止外层节点播放。

### 8.3 同一台词重复多次

通常是没有执行条件分支，而是把 `111` 下的所有分支全部展开。应检查 `:conditional` 节点是否存在，以及播放时是否只选择一个真/假分支。

### 8.4 图片报错或不显示

检查：

- 是否使用 `$game_troop.screen`；
- 231/232 参数是否按原版顺序传递；
- 图片文件是否存在于 `Graphics/Pictures`；
- 混合模式是否为有效值；
- 场景是否仍是 `Scene_Battle`。

### 8.5 某些事件内容缺失

当前解析器只处理对话、选项、条件、公共事件、图片和音效等常用指令。动画、角色图形、变量/开关修改、战斗处理、脚本副作用等指令会被跳过。遇到新的事件指令时，应先确认是否需要“显示效果”，再决定是增加节点还是保持跳过。

## 9. 维护注意事项

- 修改解析器后必须执行 `ruby -c Patch\\zzzz_gouqi_Research_Mod.rb`。
- 不要把 `Patch/zzzz_gouqi_Research_Mod.rb.txt` 当作实际运行文件；运行文件是 `.rb`。
- 不要删除原版 `117`、`231`、`232`、`235`、`250` 参数中的字段。
- 选择索引保持 0-based，不要改成 1-based。
- 所有新增代码注释使用英文。
- 修改窗口定位后，必须测试普通搭话模拟、香水模拟和战斗修改菜单，确保定位标记已清理。
- 事件解析中的 `rescue` 只能防止单个不支持内容导致崩溃，不能悄悄吞掉关键流程错误；遇到流程截断时应优先检查实际异常。
