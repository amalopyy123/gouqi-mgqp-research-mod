# 研究修改器使用说明

## 当前版本

- Mod 文件：`Patch\zzzz_gouqi_Research_Mod.rb`
- 加载顺序：该文件名以 `zzzz` 开头，会在现有补丁之后加载。
- 数据改动：不修改 `Data` 目录中的原始数据库文件。

## 使用方式

1. 使用当前已有的补丁启动方式进入游戏。
2. 打开游戏菜单，选择 `研究修改器`。
3. 选择 `角色` 会弹出当前队伍成员列表；确定切换修改器的目标角色，取消则保持原角色并返回修改器菜单。
4. 选择 `切换当前角色职业` 或 `切换当前角色种族`，从完整列表中选择目标后，再输入切换后的职业/种族等级；范围为该职业/种族数据库设定的 `1～最大等级`。
5. 升高职业/种族等级时会按原版规则学习相应等级技能；降低等级时不会删除已经学会的技能。取消等级输入会返回职业/种族列表，并且不会执行切换。
6. 修改器会在该角色第一次切换前自动保存备份。
7. 使用 `保存当前角色备份` 可用当前状态覆盖备份；使用 `恢复当前角色备份` 可恢复该备份。

## 修改当前人物等级

1. 在 `研究修改器` 中先通过 `角色` 列表选择目标人物。
2. 选择 `修改当前人物等级：当前等级`，会在画面中央打开四位数字输入窗口。
3. 左右键移动数位，上下键修改当前数位；允许范围为 `0001～9999`。
4. 确定后调用游戏原有的基础等级修改接口，并自动保存该角色第一次修改前的备份。
5. 取消会关闭数字窗口，不修改等级并返回研究修改器菜单。
6. 此功能只修改人物基础等级，不修改当前职业等级或种族等级。

## 修改当前人物好感度

1. 在 `研究修改器` 中先通过 `角色` 列表选择目标人物。
2. 选择 `修改当前人物好感度：当前好感度`，会在画面中央打开七位数字输入窗口。
3. 左右键移动数位，上下键修改当前数位；允许范围为 `0000000～9999999`。
4. 确定后修改当前形态 Actor ID 对应的原版好感度变量，并自动保存修改前的好感度。
5. 取消会关闭数字窗口，不修改好感度并返回研究修改器菜单。
6. 如果角色拥有多种人格形态，各形态好感度按原版规则使用各自的 Actor ID；请先切换到目标形态再修改。

## 修改当前角色永久属性加成

1. 在 `研究修改器` 中选择目标角色，再选择 `修改当前角色永久属性加成`。
2. 可以分别修改最大 HP、最大 MP、攻击力、防御力、魔法力、魔法防御、敏捷和幸运八项永久属性加成。
3. 属性列表会显示等级/职业基础值、装备增加值、永久属性加成、原版加成上限和当前最终能力值；最大 HP、最大 MP 还会显示当前 HP、MP。
4. 确认属性后输入新的永久加成值，可以调高、调低或设为 `0`。该操作不会直接覆盖装备、职业、种族和状态倍率计算后的最终面板。
5. 原版永久属性加成上限为：最大 HP `999999999`；最大 MP 和其他六项能力 `99999999`。最终面板仍遵守游戏原版约 `10^15` 的属性上限。
6. 降低最大 HP 或最大 MP 后，当前 HP、MP 会按原版刷新逻辑压到新的上限；提高最大值后不会自动回满。
7. 第一次修改会自动保存修改前的角色备份；`保存当前角色备份` 和 `恢复当前角色备份` 现在也会保存、恢复八项永久属性加成。
8. 本功能不解除原版属性上限。游戏伤害仍可通过技能公式和倍率达到几十次方，但不会因为属性输入本身写入无限大或超出浮点安全范围的数值。

## 当前角色全职全种满级

1. 在 `研究修改器` 中选择目标角色。
2. 选择 `当前角色全职全种满级`。
3. 该角色的全部职业和种族都会记录为最高等级，并获得相应等级可学习的技能；当前装备、当前职业和当前种族不会被切换。
4. 返回普通菜单并使用游戏原有的 `保存` 功能写入测试存档。保存后结果会保留，不需要再次逐项切换。

## 设置全角色好感度

1. 在 `研究修改器` 中选择 `全员好感度`。
2. 会先弹出 7 位数输入窗口，默认值为 `30000`，可输入 `0～9999999`；确认后才写入。
3. Mod 会遍历全部有名字的 Actor 记录，并将原版好感度变量 `NWConst::Var::ACTOR_REL_BASE + Actor ID` 设为输入值。
4. 主人格和副人格的 Actor ID 都会写入，便于切换形态后保持对应好感度。
4. 返回普通菜单并使用游戏原有的 `保存` 功能写入测试存档。

## 全可入队角色加入候补

1. 在 `研究修改器` 中选择 `全可入队角色加入候补`。
2. Mod 会遍历设定 ID 范围内的 Actor 记录，将有名字且 `persona_kind` 不为 `:sub` 的角色加入候补；默认范围覆盖全部 Actor。
3. 不判断是否官方可招募或是否属于剧情角色，因此 `カオス`、`冬のアリス`、`虚竜` 等角色会自动包含。
4. 此操作不会修改当前战斗队伍；请使用游戏原有的队伍编成界面让候补角色出战。
5. 完成后使用普通菜单的 `保存` 功能写入测试存档。

副人格不会作为独立候补加入，以免与主人格重复；请通过“切换当前角色形态”或对话中的“形态修改（无视事件）”处理形态。

### 编队报错二分定位

1. 关闭游戏，准备一个从未执行过全入队的干净测试存档；每轮测试都重新载入它。
2. 编辑 `Patch\zzzz_gouqi_Research_Mod.rb` 顶部的 `RECRUIT_ACTOR_ID_MIN` 和 `RECRUIT_ACTOR_ID_MAX`。默认值为 `1` 和 `9999`，表示当前待测的闭区间。
3. 先以默认区间运行全入队并打开原生编队界面，然后记录上下限并取中点。先测试前半段；报错则保留前半段，不报错则改测后半段。
4. 每次均从干净存档重测，直到上下限相同。
5. 将最终 ID 和原生报错窗口的完整文本或截图提供出来，再将该 ID 写入正式排除规则。

Actor `787` 另有运行时类别兼容：脚本会将其 `サキュバス` 类别替换为 `淫魔`，不需要修改 `Data\Actors.rvdata2`。

Actor `695`（`クレオ・アドラ`）的原版入队事件位于 `Map103`、事件 `36`，其中遗漏了 `move_actor_ex` 的参数。Mod 仅在该事件的空参数调用中自动补入 `695`，不修改地图数据库；其他事件若漏传参数仍会保持报错，便于继续定位。

## 偷盗必定成功

1. 在 `研究修改器` 的“全体与系统操作”区域选择 `偷盗必定成功：关`，显示变为 `开` 后生效。
2. 开启后，带普通偷盗或强制偷盗效果的技能会绕过未命中、回避和格挡，同时普通偷盗效果会跳过自身的随机失败。
3. 已经被偷空的类别仍会显示没有物品；原版剧情或系统使用 `STEAL_FAIL` 开关禁止偷盗时仍不会获得物品。
4. 再次选择该菜单可关闭功能；开关状态保存在游戏存档中。

如果一个攻击技能因装备或能力被附加了偷盗效果，该技能的伤害部分也会随整项技能一起必定命中；没有偷盗效果的技能完全不受影响。

原版普通偷盗判定为 `rand × 分母 < 使用者偷盗倍率`，因此单个候选物品的成功率可理解为 `min(偷盗倍率 ÷ 分母, 100%)`。基础偷盗倍率至少为 `1.0`；例如分母为 `10` 时基础成功率为 `10%`，拥有 `200%` 偷盗成功率特征时倍率为 `2.0`，成功率为 `20%`。

## 乳搾り必定成功

1. 在 `研究修改器` 的“全体与系统操作”区域选择 `乳搾り必定成功：关`，显示变为 `开` 后生效。
2. 开启后，公共事件 `12（乳搾りスキル用）` 中的获得ミルク随机判定会固定为成功。
3. 适用于 `メイドの乳搾り`、`神技の乳搾り` 等调用同一原版公共事件的技能，不修改技能数据库。
4. 只覆盖乳搾り事件对结果变量 `11` 的随机赋值，不影响其他公共事件、普通随机变量或偷盗判定。
5. 再次选择该菜单可关闭功能；开关状态保存在游戏存档中。

## 物品必定掉落

1. 在 `研究修改器` 的“全体与系统操作”区域选择 `物品必定掉落：关`，显示变为 `开` 后生效。
2. 开启后，被击败敌人的每个有效掉落物品槽都会必定掉落一次，不再执行原版掉落率随机判定。
3. 空掉落槽不会生成物品；只有实际被击败并进入战斗奖励结算的敌人才会处理掉落。
4. 不影响偷盗、牛奶获取、宝箱、剧情事件奖励或脚本直接给予的物品。
5. 再次选择该菜单可关闭功能；开关状态保存在游戏存档中，旧存档默认关闭。

原版每个掉落槽的判定为 `rand × 掉落分母 < 掉落倍率`，单槽成功率可理解为 `min(掉落倍率 ÷ 掉落分母, 100%)`。本开关只跳过这项随机判定，仍保留原版图鉴掉落计数和战斗奖励发放流程。

## 获得全部内裤

1. 内裤列表扫描防具 ID `1801～2097`，不再跳过名称为空的防具；只要数据库中存在对应防具，就会加入列表。
2. 因此防具 ID `2024` 会和其他空名称防具一起被计入并一键获取。
3. 该功能按防具对象发放 1 件；已经拥有的项目不会重复增加。

## 我方攻击必中必杀

1. 在 `研究修改器` 的“全体与系统操作”区域选择 `我方攻击必中必杀：关`，显示变为 `开` 后生效；状态保存在当前存档中。
2. 开启后，我方角色对敌方使用的技能和物品会在原版命中判定后清除未命中、回避和格挡结果；敌人对我方的攻击以及我方对队友使用的技能不受影响。
3. 对敌方使用 HP 伤害或 HP 吸收类型的技能时，结算伤害至少等于目标当前 HP，并在原版伤害处理后确保目标 HP 为 `0`；治疗、辅助和仅附加状态的技能不会因为这个开关直接杀死目标。
4. 手下留情、金属身体、伤害墙、毅力保留 1 HP 等减伤机制会被致死处理覆盖，但原版死亡状态、死亡技能、最终发动、复活和 BOSS 阶段事件仍然保留。
5. 多阶段或带自动复活的敌人通常需要每个阶段再次攻击一次；该功能不会直接删除敌群或强制结束战斗，以免跳过掉落、图鉴统计和剧情事件。
6. 反射后实际目标为我方角色时不会触发必杀；持续伤害、地图伤害和敌人之间的伤害也不受影响。

## 当前角色学习妖術

1. 先通过 `角色` 菜单选择目标队伍成员，再选择 `学习当前角色妖術`。
2. 列表首项 `全部学习` 会让当前角色学会所有可通过原版ラーニング机制获得、且该角色允许学习的妖術。
3. 也可以选择单个妖術进行学习；已学会的技能会显示 `（已学会）`，角色专属限制禁止学习的技能会显示 `（不可学习）`。
4. 技能清单来自原版技能数据中的 `learning_skill` 映射，不单纯依赖技能 ID 范围，因此会自动包含实际可被ラーニング的新技能。
5. 学习操作调用角色原版 `learn_skill`，不会赋予ラーニング特征，也不会修改职业、种族或技能数据库。
6. 首次学习前会自动保存当前角色备份，可使用 `恢复当前角色备份` 还原其技能状态。

## 严格同步当前人物等级

1. `严格同步当前人物等级` 仍修改角色的基础等级，范围为 `1～9999`。
2. 降低等级时，不会删除已经学会的技能；超过当前基础等级要求的角色固有能力只会暂时从能力装备栏卸下，使其最大 HP 等属性效果停止生效。
3. 重新达到能力要求等级后，修改器会尝试恢复由严格同步暂时卸下的能力；如果当前 AP 不足或职业条件不满足，则保留为已学习但未装备状态。
4. 成长道具写入的永久参数、普通装备、职业等级和种族等级不是基础等级成长，因此不会被清除或降低。
5. 角色备份现在同时保存已学习能力、能力装备配置和严格同步抑制记录；旧版已经建立的备份不包含这些新增字段，但仍可恢复原有等级和技能数据。

## 一键补齐全部パンツ

1. 在“全体与系统操作”区域选择 `一键补齐全部パンツ（当前数/289）`。
2. パンツ收藏使用防具 ID `1801～2097`；当前数据库中该区间有 297 个槽位，其中 289 个有名称、8 个为空名保留槽。
3. 功能会跳过空名防具，并跳过队伍已经持有或由成员装备的パンツ，只为缺少的项目各增加一件。
4. ID `1933（ギャルのパンツ）` 虽未被任何敌人的第 4 类偷盗表引用，但属于该パンツ防具区间，因此也会补齐。
5. 范围外名称包含“パンツ”“下着”等文字的数据可能是系统类型、能力载体或其他装备，不属于敌人 `盗める下着` 收藏，因此不会加入。
6. 直接获得不会伪造敌人偷盗次数，也不会自动把所有敌人图鉴中的 `盗める下着` 标记为已经偷过。

## 一键补齐全部ミルク

1. 在“全体与系统操作”区域选择 `一键补齐全部ミルク（当前数/706）`。
2. 乳搾り公共事件使用普通物品 ID `1001～1741`；该区间共 741 个槽位，其中 706 个有名称、35 个为空名保留槽。
3. 公共事件 `12（乳搾りスキル用）` 实际引用的奖励物品正好是这 706 个有名项目，没有范围外奖励，也没有有名但未引用的项目。
4. 功能会跳过空名物品和队伍已经持有的ミルク，只为缺少的项目各增加一个，重复点击不会继续增加数量。
5. 范围外的 `33（魔物のミルク）`、`342（ミルク）`、`460（しあわせミルク）` 是其他用途的普通物品，不属于角色乳搾り奖励，因此不会加入。
6. 直接获得不会执行乳搾り对话、成功率判定或相关图鉴统计，只补齐队伍物品库存。

## 一键获取全部结婚戒指

1. 在“全体与系统操作”区域选择 `获得全部结婚戒指（当前数/20）`，位置紧接在“获得全部牛奶”之后。
2. 功能获取护具 ID `8001～8020`，从 `8001（終焉を添い遂げる者の指輪）` 到 `8020（エデンの土）`，当前数据库共 20 件且均有名称。
3. 功能会同时检查库存和角色已装备护具，只为尚未持有的项目各增加一件；重复点击不会继续增加数量。
4. 这 20 件护具不属于动态附魔模板范围，可以通过原版护具库存流程直接获得。

## 公共事件查看

1. 在“全体与系统操作”区域选择 `公共事件查看`。
2. 输入公共事件起始 ID 后，每批加载最多 200 个有数据的公共事件；列表顶部和底部都可以重新输入起始 ID，并支持上一批、下一批。
3. 选择公共事件后，可以查看 ID、名称、指令数量和事件指令摘要；详情支持上下滚动和左右翻页。
4. 查看器会尽量把显示文字、公共事件调用、开关、变量、物品、武器和防具显示为可读名称或 ID。
5. 这是只读调试功能，不会执行公共事件，也不会修改开关、变量、物品、地图或存档数据。

## 角色图鉴

1. 在“全体与系统操作”区域选择 `角色图鉴`。图鉴收录角色数据库中全部 888 个有名称角色，不受入队状态、原版图鉴解锁状态或事件开关限制。
2. 左侧角色列表按数据库 ID 从小到大显示，格式为 `ID　角色名`；为避免一次创建过高位图，每批显示 100 个角色，并提供上一批、下一批和返回。
3. 在角色列表中移动光标时，右侧只显示固定操作提示，不加载或绘制角色备注，以兼容 MTool 翻译注入层。
4. 确认角色后可以选择 `魔物备注`、`固有アビリティ`、`Picture路径`、`Cut-in图片查看` 或 `返回`；没有 Cut-in 配置的角色会将该项目置灰。
5. 只有确认查看类型后，右侧全高大窗口才会读取并显示内容。`Picture路径` 会根据角色 ID 读取原版 `ACTOR_IMAGE` 映射，显示例如 `Graphics/Pictures/80_worldbreaker_st01` 的普通 Picture 相对路径及文件名。
6. 同一页面还会读取角色技能台词配置中的全部 `ct_pic`，并在每条路径前显示对应技能名和技能 ID；同一技能配置多个 Cut-in 时会分别显示，角色也可能没有 Cut-in。
7. 所有正文统一使用 18 号字体，数据库中的超长单行会按 26 个字符安全换行，但不会删除或改写内容。
8. 阅读状态下，上下键逐行滚动，左右键或 L/R 键整页滚动，取消键返回查看类型菜单。
9. `固有アビリティ` 读取原版 `NWConst::Library::ACTOR_FIX_ABILITY`，并优先沿用角色当前觉醒状态对应的 `ability_id`；这不是角色升级学习技能用的 `peculiar_skill`。

7. `直接获得淫らな魂` 只在尚未持有时直接增加一件，不修改 BF 奖励进度；已经持有时该快捷项会禁用。

9. 累计小奖牌兑换数使用变量 `55`，累计大奖牌兑换数使用变量 `59`。它们不是当前持有数量，修改可能影响成就或事件判定。

## 地图与事件检查

1. 在“全体与系统操作”区域选择 `地图与事件检查`，可以直接查看当前地图，或输入起始 ID 后从地图数据库分页选择。
2. 当前地图入口的菜单文字直接显示地图 ID 和地图名称，底部帮助窗口同时显示玩家坐标；按 ID 选择每批最多加载 100 张地图，提供重新输入、上一批和下一批。该功能只读取地图数据，不会传送玩家或执行地图事件。
3. 选择地图后会列出全部地图事件，包括名称为空的事件；列表显示事件 ID，帮助窗口显示地图 ID、事件坐标和事件页数量。
4. 选择事件后再选择具体事件页。详情首先显示事件页出现条件，包括开关、变量、独立开关、持有物品和队伍角色，并同时显示当前存档中的实际状态。
5. 详情随后扫描该事件页的事件指令，显示直接出现的开关操作、变量操作、条件分歧、独立开关操作和公共事件调用；开关和变量会同时显示数据库名称。
6. 详情窗口使用上下键逐行滚动，左右键或 L/R 键整页翻动，取消返回事件页列表。
7. 公共事件调用目前只显示公共事件 ID 和名称，不会递归展开公共事件内部内容。事件中的动态脚本无法完全推断；直接包含 `$game_switches`、`$game_variables` 或 `$game_self_switches` 的脚本会显示截断后的提示文本。
8. 事件页条件和指令引用本身为只读；事件页列表末尾可修改该事件的独立开关，但不会修改原始 `Data` 文件。
9. 本作使用扩展地图编号：普通目录使用 ID `1～999`，`Data/Map/Data` 中的地图使用 `1001～1999`，`Data/Map2/Data` 中的地图使用 `2001～2999`。检查器会按游戏原版的分段规则合并地图名称并读取对应文件。
10. 选择地图事件后，事件页列表末尾提供 `查看与修改独立开关 A～D`。列表会显示该事件四个独立开关的当前 ON/OFF 状态，选择后可明确设为 ON 或 OFF。
11. 独立开关使用完整键值 `[地图ID, 事件ID, A/B/C/D]`；相同事件 ID 在不同地图中互不影响。修改当前地图的独立开关会立即刷新事件页，修改其他地图的独立开关会在以后进入该地图时生效。
12. 独立开关修改只影响当前游戏状态，使用原版保存功能后才会写入存档。错误修改可能让宝箱重复开启、NPC 对话重置或一次性剧情重新执行，建议先保存独立存档。
13. 事件列表和事件页列表会显示生效页。查看当前地图时，读取运行中的 `Game_Event` 实际页面；若事件已被暂时消除或当前没有满足条件的页面，则显示 `无`。
14. 查看非当前地图时无法取得运行时事件对象，因此会按照当前存档的开关、变量、独立开关、物品和队伍状态推算生效页，并明确标记为 `按当前存档推算生效`。
15. 原版按事件页从后向前判定，最后一个满足条件的页面优先。列表会分别标记 `当前实际生效`、`条件未满足`、`条件满足但被后页覆盖`；修改独立开关并返回后会立即刷新这些标记。

## 开关与变量修改

1. 在“全体与系统操作”区域选择 `开关与变量修改`，再选择 `修改开关` 或 `修改变量`。该菜单位于 `地图与事件检查` 后面，便于先查事件引用的 ID，再进行调试修改。
2. 输入数据库起始 ID 后，每批连续显示 200 项；不跳过无名称条目。列表格式为 `ID　数据库名称：当前值`，顶部和底部均可重新输入起始 ID，并支持上一批和下一批。
3. 选择开关后会显示完整 ID、名称和当前状态，可以明确设置为 `ON` 或 `OFF`；设置相同状态也允许执行。

5. 如果原变量保存的是字符串、数组或其他非数字对象，列表会显示截断后的 `inspect` 内容；打开整数输入时以 `0` 为起始值，确认后会把该变量替换为整数。
6. 修改通过原版 `$game_switches[id] = value` 与 `$game_variables[id] = value` 写入，因此会立即请求刷新地图事件页；返回地图后，满足条件的自动执行或并行事件可能马上启动。
7. 修改只影响当前运行中的游戏状态；使用原版保存功能后才会写入存档。该功能不会修改 `Data/System.rvdata2` 中的名称，也不会修改地图或公共事件数据库。
8. 建议修改剧情开关或变量前先保存到独立存档。错误组合可能导致剧情跳过、事件重复、NPC 消失或自动事件循环。
9. 菜单内置已知卡关提示：前章卡在アモス聖山时，将开关 `2479（アモス聖山暗転）` 设为 `OFF` 即可下山；终章卡在新人类宴会时，将变量 `1150（サラサ空賊団イベント）` 设为 `17`，再与サラサ、アリス对话即可结束该段事件。
10. 戒指事件提示：变量 `1401（ルシフィナ指輪イベント）` 设为 `0` 可以重复拿戒指，设为 `1` 可以重复送戒指；变量 `1402（指輪誰に渡したか）` 记录戒指交给了谁。变量类型入口、起始 ID 输入、列表光标和数值输入窗口都会显示相应说明。

## 敌人诱惑事件无视 HP

1. 原版 `メロメロの香水`（防具 ID `1740`）会促进战斗中的敌人诱惑事件；通常难度下，普通香水约在敌人 HP 降到 `50%` 以下时满足判定。
2. `究極の香水`（防具 ID `1741`）会把原版 HP 判定范围放宽一倍；通常难度下约为敌人 HP `100%` 以下，因此可能在几乎没有受伤时触发。
3. 开启 `敌人诱惑事件无视HP` 后，公共事件 `6（敵会話・誘惑判定）` 的“变量 13 等于 1”入口分支和公共事件 `203（会話誘惑３　各敵の誘惑部分）` 的“当前 HP 严格小于阈值”分支会直接判定为成立；不需要装备两种香水，也不受敌人当前 HP 影响。
4. 开关只跳过 HP 条件；敌人必须拥有对应诱惑事件，ルカ和敌人仍须处于原版允许状态，并继续遵守每次判定流程只执行一次等原版限制。
5. 开关状态保存在 `$game_system` 中，会随存档保存；关闭后立即恢复原版香水和 HP 判定。
6. 开关不会在打开菜单时立刻播放诱惑；它会在战斗中的下一次原版“敌会话・诱惑判定”执行时生效。

## 敌人诱惑事件禁止

1. 在研究修改器的“战斗与功能开关”区域开启 `敌人诱惑事件禁止`。
2. 开启后，公共事件 `6（敵会話・誘惑判定）` 调用诱惑部分 `203（会話誘惑３　各敵の誘惑部分）` 时会直接跳过，因此无论是否装备 `メロメロの香水`、`究極の香水`，也无论敌人 HP 多少，都不会进入诱惑事件。
3. 公共事件 `204（会話誘惑４　各敵の会話部分）` 不会被阻止，敌人的普通随机对话仍可正常触发。
4. 如果 `敌人诱惑事件禁止` 与 `敌人诱惑事件无视HP` 同时开启，禁止开关优先：前者跳过事件203，后者即使强制条件成立也不会播放诱惑。
5. 开关状态保存在 `$game_system` 中并随存档保存；关闭后恢复原版装备、随机数和 HP 条件流程。

## 战败后跳过败北事件

5. 开关状态保存在 `$game_system` 中并随存档保存；旧存档默认关闭。

## 敌我全员誘惑免疫

1. 在研究修改器的“战斗与功能开关”区域开启 `敌我全员誘惑免疫`。
2. 开启后，我方角色和敌方成员都无法获得 `誘惑（状态ID 26）`；技能成功率、状态抗性和强制附加均不能绕过该免疫。
3. 开启瞬间会解除当前战斗中敌我双方已经存在的誘惑状态，之后进入战斗时也会再次清理残留状态。
4. 该免疫优先于研究修改器的手动赋予功能；开启时，`战斗修改 → 异常状态 → 誘惑 → 赋予誘惑` 会显示为不可用，但解除誘惑仍可使用。
5. 本开关只处理战斗状态 `誘惑`。敌人的香水诱惑公共事件属于另一套机制；直播时建议同时开启 `敌人诱惑事件禁止`。
6. 开关状态保存在 `$game_system` 中并随存档保存；旧存档默认关闭。

## 战斗修改菜单

1. 在研究修改器的“战斗与功能开关”区域开启 `战斗修改菜单`，战斗队伍指令会新增 `战斗修改`。
2. 当前结构为 `战斗修改 → 异常状态 → 誘惑`；搭话播放功能已经移动到 `战斗对白模拟 → 搭话模拟`。
3. `誘惑` 下可以选择 `赋予誘惑` 或 `解除誘惑`，目标可以是单独的我方角色、单独的敌方成员、我方全体、敌方全体或敌我全体；全体操作与单体操作都会经过最终确认。
4. `赋予誘惑` 直接写入状态并初始化正常持续回合，无视目标的誘惑抗性、状态免疫、技能命中率和成功率；状态本身的行动限制与自然解除仍按原版执行。
5. `解除誘惑` 使用原版状态解除流程；目标列表会用 `【誘惑】` 标记当前已中状态的成员，没有誘惑的单体或全体项目不可执行解除。
6. 所有修改均不消耗战斗回合。`敌我全员誘惑免疫` 开启时，免疫开关优先，不能通过本菜单重新赋予誘惑。

## 战败事件

1. 在“全体与系统操作”区域选择 `战败事件`，输入敌人数据库起始 ID；每批最多加载 200 个可播放项目。
2. 列表格式为 `敌人ID　E战败事件ID　敌人名`，帮助窗口同时显示基础敌人 ID；顶部和底部都可重新输入起始 ID，并支持上一批、下一批和返回。
3. 菜单跳过名称为空、对应公共事件不存在，以及原版标记为禁止战败回想的敌人。
4. 扩展敌人按照 `enemy.lose_event_id` 映射到基础事件，并按战败事件 ID 去重，避免相同事件重复出现。
5. 确认后使用 `Scene_Novel` 播放流程；游戏版本提供原版敌人回想背景表时优先读取该表，否则使用进入小说场景前的画面截图作为背景。功能不会创建敌群或开始战斗，也不要求该事件已经在原版图鉴中解锁。

## 反省会查看

3. 列表会跳过空名称、没有败北事件、公共事件不存在或原版禁止回想的敌人。
4. 确认后直接播放原版“反省会に出る”的第一个分支，不显示“反省会に出ますか？”、难度选择或轮回返回选项。
5. 播放仍使用原版 `Scene_Novel`，不会创建敌群或开始战斗；播放期间会阻止事件传送，因此不会改变当前地图和角色坐标。
6. 反省会播放结束后自动回到当前敌人列表，并重新开启队伍行进显示；只有在列表中按取消键才会退出反省会查看。普通 `战败事件` 也会从事件开头播放、自动回到原列表，并同样保护当前地图和坐标。

- 职业和种族切换调用游戏原有的 `change_class` 方法，不直接写入 `@class_id` 或 `@tribe_id`。

- 该版本故意绕过转职界面的前置等级和道具限制，仅用于研究组合效果。
- 一键操作会自动使用已有备份；如果希望把当前状态设为新的恢复点，请先选择 `保存当前角色备份`。
- 尚未在实际游戏窗口中完成点击测试；首次使用应在独立测试存档中进行。

4. 开启状态会在玩家更新、读档和上下交通具后继续生效；关闭后仍保留原版飞艇的穿墙状态。

## 不遇敌

1. 在研究修改器的“战斗与功能开关”区域中，`不遇敌：开/关` 位于 `穿墙模式` 正下方。
2. 开启后，地图步行不会触发原版随机遇敌；切换开关时会重新生成遇敌计数，关闭后不会立刻因为旧计数耗尽而进入战斗。
3. 事件指令启动的剧情战斗、地图上的接触事件、BOSS 战和研究修改器的 `自定义战斗` 不受影响。
4. 开关独立保存在 `$game_system`，不会修改原版 `encounter_disabled` 状态；旧存档默认关闭。

## 原版禁止遇敌状态

1. 研究修改器的 `原版禁止遇敌：开/关` 直接读取和修改原版 `$game_system.encounter_disabled`。
2. 该状态不是数据库开关或变量，因此没有开关 ID；它对应事件指令“禁止遇敌 / エンカウント禁止”。
3. `原版禁止遇敌` 与修改器自己的 `不遇敌` 独立，两个都关闭时才不会因这两项设置阻止原版随机遇敌。
4. 切换后会重新生成地图遇敌计数；剧情战斗、接触事件和研究修改器的 `自定义战斗` 不受该状态直接限制。
## 实验功能：敌方属性倍率

1. 研究修改器主菜单底部新增独立的 `实验功能` 入口；进入后显示 `实验功能总开关`、`敌方属性倍率` 和 `返回`。
2. 总开关默认关闭。关闭时保留所有子项设置，但实验功能全部不生效；重新开启后恢复使用之前保存的倍率。
3. 敌方属性倍率输入范围为 `0～99`，默认保存为 `1倍`。`0` 和 `1` 都保持原值；总开关开启时，`2～99` 表示将敌方能力乘以对应倍数。
4. 倍率同时作用于敌人的最大HP、最大MP、攻击、防御、魔力、精神、灵巧和速度，并在本作难度修正、状态和强化／弱化等原版计算完成后应用。
5. 倍率只作用于 `Game_Enemy`，不会提高我方角色、地图事件或数据库原始数值；敌方信息窗口会显示倍率后的实际能力。
6. 战斗中切换总开关或倍率时，会按原百分比调整敌人的当前HP/MP，避免提高倍率后敌人突然变成残血，或降低倍率时改变生命比例。
7. 此功能用于极端数值和战斗稳定性实验，高倍率可能使战斗时间显著增加，建议使用独立测试存档。

## 修改地图跟随显示人数

1. 在 `研究修改器` 主菜单的“角色与队伍”区域选择 `地图跟随显示人数`。
2. 输入范围为 `0～99`，数值不包含队首玩家；例如输入 `3` 时，地图最多显示玩家加3名跟随者。
3. 设置保存在 `$game_system` 中并随存档保存，不占用游戏变量。旧存档第一次使用时默认采用 `3`。
4. 跟随者按当前编队顺序显示，超过实际编队人数的槽位为空；候补角色不会因为此设置自动进入当前编队。
5. 修改后返回地图时会重建跟随队列和地图人物精灵。设置过高可能造成明显卡顿，测试后可随时改回 `3` 或 `0`。
4. 例如输入 `12`，变量 56 会保存为 `4`；输入 `20`，变量 56 会保存为 `12`。
5. 该功能修改的是编队容量，不会把战斗出场人数从原版的 4 人改大。
6. 如果把上限降低到当前编队人数以下，超出的成员可能会在下一次打开或刷新编队时转入候补。

2. 开启后，Mod 会在符合结构的候补角色互动菜单中新增 `魔王城全对话`，不再限制地图 ID；地图 228 只是其中一个示例。
3. 进入后直接显示统一列表：`未送戒指（默认对话）`、`已送戒指（戒指专属对话）`、带 Actor ID 的具体队友对话以及 `返回`，不再先进入戒指状态子菜单。
4. 未送戒指只播放当前事件页在没有匹配队友时使用的默认对白；已送戒指只播放以变量1402判断的戒指专属对白，不会继续自动打开队友列表。
5. 戒指专属对白按事件中的 `变量1402「指輪誰に渡したか」 == 对象编号` 条件自动识别，不限定ソニア；同一事件存在多个戒指分支时会再列出分支编号和首句预览。
6. 具体队友对话会扫描当前事件页按 Actor 标签配置的对白，并在名称前显示 Actor ID。
7. Actor 数据库名称为空时，会依次尝试游戏角色实例名称和对白中首个 `【角色名】`；例如 ID 708 会显示为 `カオス`，不再只显示空白名称。
8. 播放任意对白后会重新显示同一个全对话列表，可以继续查看其他项目；只有选择 `返回` 或按取消键才关闭列表并返回原互动菜单。
9. 所有查看功能只显示对白文字和头像，不修改变量1402，也不执行事件中的好感度、道具、开关、入队、音效、画面切换或其他分支效果。
10. 关闭开关时不会注入 `魔王城全对话`，实际事件对话也恢复原版入队判断；该功能不影响魔王城形态变化。
11. 两个原有开关状态继续分别保存在 `$game_system` 中，以兼容旧存档。旧存档中两者状态不一致时显示 `部分开启`，点击后会统一全部开启。
## 战斗对白模拟

1. 在研究修改器的“战斗与功能开关”区域开启 `战斗对白模拟`。开启后，战斗队伍指令菜单新增同名入口。
2. 主菜单依次为 `搭话模拟`、`特殊战斗台词`、`我方技能台词`、`敌方技能台词`、`效果反应台词` 和 `双方组合预览`；所有入口只播放文字与头像，不发动技能、不结算伤害、不修改状态、不获得物品，也不推进战斗回合。特殊类别的候选会按当前人物的完整列表连续编号，不再因切换技能而反复显示候选1。
3. `搭话模拟` 先从当前战斗的敌我双方选择发起者，再选择敌方目标和搭话内容；敌方发起者也可以选择自己作为目标。发起者存在技能ID `2109「話し掛ける」` 的开场台词时会先播放该台词，没有开场台词时直接播放目标敌人的对话。存在原版选项时使用原版选项窗口，并只播放所选回应，不执行事件效果。
4. `我方技能台词` 列出当前参战角色已经学会技能所对应的台词；按角色当前 `word_id` 读取，所以形态变化后可能显示不同内容。
5. `敌方技能台词` 先选择当前在场敌人，再选择 `可用技能台词`、`全部技能台词` 或 `击败与异常台词`。可用技能只取 `all_actions`，全部技能会读取完整人物模板。
6. `特殊战斗台词` 进入后提供 `对话`、`选项回应`、`技能分类台词`、`变身类`、`爱玩` 与 `誘惑反应`。`技能分类台词` 依次选择武技、魔法、职技、魔物技（种族技）或其他技能，再选择剑技、ヒーロー技、踊る、歌う等具体技能类型，最后从当前战斗的敌我双方选择人物并查看台词。筛选使用数据库技能类型 ID，例如 `ヒーロー技=33`、`踊る=37`、`歌う=38`；会检查每条对白关联的全部技能 ID 和技能的全部类型，不要求角色当前已经学会或能够使用。同一个台词数据键关联多个同类型技能时只显示一条，并在技能名后加 `等`。
7. `选项回应` 解析公共事件的标准选项指令，菜单直接显示“选项名称（提问内容）”；嵌套选项使用“外层选项 → 内层选项”表示。确认后只播放提问和该选项对应的回答，不执行好感度、变量、物品等效果。脚本生成且无法识别的选项会回退为候选编号，避免对白消失。
8. `爱玩` 读取技能 `28「遊ぶ」` 调用的公共事件 `39「スキル：遊ぶ共通」`，再按当前我方角色ID定位公共事件40～86中的专属分支，提取带头像或角色名的对白。被动能力 `遊び好き` 通过防具效果 `1737「うさみみバンド」` 以50%概率把行动替换为该技能；查看时不要求当前装备能力。一次随机爱玩结果中的多个文字窗口会合并为一条候选，确认后按原顺序连续播放。原版这套公共事件只按我方角色ID分支，因此爱玩分类不显示敌方成员。
9. `誘惑反应` 会同时读取对应技能的原版技能消息（`message1`、`message2`）和 `word_y...` 诱惑反应条目。播放顺序是诱惑反应台词→技能原版消息；敌方技能攻击主角时，技能消息中的 `\\E` 会替换为当前1号角色名称（通常是鲁卡）。没有 `\\U/\\E` 的 `message1` 会按原版战斗日志规则自动在开头拼接使用者名称，`message2` 则不拼接。查看器不要求角色当前真的处于誘惑，也不要求该技能已经学会。列表预览只显示第一句，完整内容在确认后播放。
10. 敌方列表也会显示当前敌人角色模板中存在的 `word_y...` 原始配置，方便研究共用模板；但原版敌方台词条件通常不接受 `:temptation?`，所以敌方项目不一定会在正常战斗中自然触发。没有对应配置的人物显示为0条并置灰。
11. `效果反应台词` 同时列出当前我方与敌方。敌方可能包含乳搾り成功、乳搾り失败、普通击败、快乐击败、捕食击败和失禁异常；没有对应配置的角色会置灰。
12. 乳搾り成功反应从公共事件 `12「乳搾りスキル用」` 的目标敌人分支读取，强化或混沌变体会使用基础敌人分支并替换当前名称；失败只播放原版失败文字，不进行成功率判断。
13. `双方组合预览` 先选择我方或敌方释放者的一条技能台词，再选择我方或敌方目标的一条效果反应，最后按“释放台词→目标反应”的顺序连续播放。
14. 组合预览采用手动配对，不会猜测技能实际效果。因此可以自由组合调试，也可能组合出原版战斗中不会自然发生的对白。
15. 普通启动时台词列表每批最多显示 100 条。检测到 MTool 时改为每批 23 条，每项第一行显示技能信息，第二、三行显示经过控制符清理和长度限制的自动换行预览；取消键可逐级返回。
16. 所有入口只提取并播放文字与头像，不执行技能、选项、变量、好感度或其他事件效果；开关状态保存在 `$game_system` 中并随存档保存，旧存档默认关闭。




## 全对话的入队条件处理

1. 研究修改器中的 `全对话` 会同时启用对话浏览和无视入队条件，不再提供单独的“对话无视入队条件”菜单。
2. 开启后，事件中的 `actor_label_jump` 会把数据库中所有 Actor ID 都作为可匹配的对白标签，不要求角色加入队伍或候补。
3. 对于带有显示文字的“角色在队伍中”事件条件，Mod 会直接判定条件成立，因此可以触发对应角色对白。
4. 该功能只修改对白执行时的判断，不会把角色实际加入队伍，不会加入候补，也不会改变队伍人数、战斗成员或入队记录。
5. 关闭后恢复原版判断；旧存档和新存档默认关闭，开关状态保存在 `$game_system` 中。
6. 不带对白文字的普通角色条件分支仍交给原版处理，避免影响非对白剧情逻辑。
## 当前音乐信息

1. 在研究修改器的“全体与系统操作”区域选择 `当前音乐信息`。
2. 信息窗口会显示当前 BGM、BGS，以及引擎最后记录的 ME 文件名，同时显示音量和音调。
3. BGM 文件位于 `Audio/BGM`，BGS 位于 `Audio/BGS`，ME 位于 `Audio/ME`；显示的是不含扩展名的数据库文件名。
4. 选择 `刷新信息` 可以重新读取当前状态；选择 `返回` 或按取消键回到研究修改器主菜单。
5. ME 是引擎最后一次记录的音乐效果，播放结束后名称可能仍然保留，因此不一定代表 ME 此刻仍在播放。

## 当前音乐悬浮窗

1. 在研究修改器的“战斗与功能开关”区域开启 `当前音乐悬浮窗`。
2. 开启后，地图和战斗画面右上角会显示当前 BGM 与 BGS 文件名；音乐发生变化时自动刷新，不需要手动打开详细信息。
3. 悬浮窗只在地图和战斗场景显示，进入普通菜单、研究修改器或存档界面时自动释放，返回地图或进入战斗时重新创建。
4. 关闭开关后，正在显示的悬浮窗会在场景更新时立即消失；开关状态保存在 `$game_system` 中并随存档保存。
5. 悬浮窗不显示 ME，因为 ME 播放结束后引擎仍可能保留最后记录；需要查看音量、音调或最后 ME 时继续使用 `当前音乐信息`。

## 开关名称表与变量名称表

1. `开关名称表.csv` 和 `变量名称表.csv` 位于 `ResearchMod` 目录，由当前 `Data/System.rvdata2` 导出。
